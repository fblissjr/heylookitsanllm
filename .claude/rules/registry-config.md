# Model registry and heylook.toml

- heylook.toml is override-only (`model_registry.py`): anything under `[scan].folders` is served with derived defaults. The merge happens at load (`ModelRouter._load_config`, startup and reload) and never writes heylook.toml. A `[[models]]` entry is served exactly as written and always wins; discovery can only add. A model is added only by placing it under a watch folder; nothing writes a new entry except an admin config edit (`update_config`).
- Match models by resolved `model_path` (`.resolve()`), never by id.
- A model's own settings live in `model.heylook.toml` in its folder (`model_importer.SIDECAR_FILENAME`), read by the scan that finds the model and layered over its derived config: provider-config fields by name, `unset = [...]` to drop a derived field, relative `*_path` values resolved against the folder. `model_path` and `id` are not settable (the folder is the model; the id is the folder name, owner decision 2026-09-24). A file that does not parse or validate rejects that model alone, named in `scan().failed`. The engine contract reports its values as configured in that file (`router.stored_in`, baseline `router.derived_configs`). The admin editor writes it (next bullet).
- Only the owner's daily server writes model settings (owner decision 2026-09-24). Every other launcher (`scripts/dev_server.sh`, the E2E harness, loop runs through dev_server.sh) sets `HEYLOOK_READONLY_MODEL_CONFIG`; every writer (`ModelService._write_toml`, the template override's write and remove, and any future `model.heylook.toml` writer) calls `model_registry.refuse_if_readonly`, and api.py maps `ModelConfigReadOnly` to 409. A new writer calls it too. Model folders and a dev server's heylook.toml are shared by every instance, so no worktree copy isolates them.
- Discovery is best-effort: a failing scan is logged and dropped, never fatal. `scan()` returns the entries and the sources that failed (a missing folder is a failure; one invalid model is rejected alone, never its whole folder). The router's `AppConfig` is `model_registry.served` and nothing else, so `served_diff` cannot disagree with the server.
- An admin edit to a discovered model (`update_config`) writes that model's `model.heylook.toml` (`ModelService._update_model_file`): only the fields set, null drops one back to derived, and a file left empty is deleted. It validates the whole effective config first. Nothing writes a heylook.toml entry any more (materialization and the enable toggle retired, v2.0.115; the `enabled` field, v2.0.119: a model in a scan folder is served, and to stop serving one you move it out). Reads never write.
- An explicit entry receives none of discovery's derived fields. Adding one field means hand-writing every other field that model needs. Before adding a field to an entry, check what discovery was giving that model and carry it, or the edit is a silent capability removal: run `scripts/served_diff.py --against <candidate>` (or `--prune`), which asks the server's own merge instead of predicting it.
- The router keeps `max_loaded_models=1` by default (LRU evict, pin, idle-unload via `idle_unload_seconds` / `unload_after_idle_seconds`).
- Every provider-config field declares when a change takes effect (`json_schema_extra={"effect": ...}`, classes in `config.EFFECT_CLASSES`). The reload set and `/v1/admin/model-options` derive from it; never hand-maintain a second copy. A new field must be classified or `config.py` refuses to import.
- Config invariants (design record: [docs/architecture/config.md](../../docs/architecture/config.md)): `reload_config()` pushes per_request defaults into loaded providers; admin responses serialize config with `exclude_unset`, and a validator that assigns derived fields must restore `__pydantic_fields_set__`; `stale_reload_fields` is server-derived and never rebuilt client-side.
- heylook.toml comments survive admin writes (`toml_comments.py`) only while their anchor is unchanged; a comment on a value you patch is deliberately dropped. Keep provenance for a value you are changing in these rule files, `sharp_edges.md` or `internal/`, not beside the value. `tomli_w` stays authoritative; tomlkit is read-only for comment extraction. Never graft comments into a tomlkit-parsed document.
- Pydantic `Field` defaults use keyword form (`Field(default=None, ...)`, never `Field(None, ...)`); this pyright build flags positional defaults as missing constructor arguments. `test_field_keyword_defaults.py` enforces it.

Why and history: [sharp_edges.md](../../docs/architecture/sharp_edges.md) "Model registry and config".
